What it is

An operations surface for a fleet of agents.

Built for a single technical operator running roughly 5 to 25 Claude Code sessions at once across personal projects, their own business, and multiple clients. It replaces a screen full of scattered terminal windows with one place where the whole fleet is visible.

The problem

Running many agent sessions makes you lose track: which one is waiting on you, what it wanted, whether you already handled it, and what you left running last night.

What it does

It externalizes that state and survives restarts. The core job is answering "which sessions are waiting on me right now, and where?" in under a second.

How it fits in

No daemon, and nothing installed inside a session. It reads Claude Code's own transcripts, session registry, and hooks, and renders real terminals.

Features

Know the state of every session at a glance.

The app fuses several signals into one honest status per session, and keeps the "did I handle that?" memory you would otherwise lose.

Awareness & status

One honest status per session

Each session gets a single coarse state — working, your-turn, needs-approval, blocked, done, or idle — fused every 1.5 seconds from the transcript, the Claude Code status hook, a live scan of the terminal buffer, and the parent/child graph.

  • Why lines. A needs-you row shows the verbatim gated command, the sentence the assistant ended on, or the name of the child a parent is blocked on.
  • Gate ledger. A SQLite-backed record of every approval and question, so nothing you haven't looked at silently disappears — and it's still there, dimmed, after you quit and relaunch.
  • Permission-gate detection. A frozen approval dialog surfaces amber instead of masquerading as busy, and clears the instant you answer.
  • Anti-flicker. Release-hysteresis holds a state steady instead of strobing, while a genuine change still snaps through immediately.

The fleet views

A 50,000-foot view of everything running

Press Cmd+Shift+E for a full-screen grid of every active session as a live-ish terminal thumbnail outlined in its state color. The outline color and tile position are genuinely real-time; only the picture is a periodic snapshot.

  • Critical-order sort. Tiles sort by urgency and animate to their new spot, so the sessions that most need you land top-left.
  • Click to dive in. Clicking a tile opens that live session, switches to its category, and highlights its row.
  • Overflow cap. The grid caps at 24 tiles and shows the rest as "+N more," so it stays legible no matter how busy the fleet is.
  • Show-idle toggle. Off by default; flip it on to see the whole live fleet instead of only what's in motion.

Session management

Launch, adopt, and remember every session

The app scans for running claude processes and adopts them without a relaunch, and can spawn its own managed sessions that accept injected prompts and cross-session messages.

  • New Session composer. One dialog sets name, category, folder, model, effort, permission mode, an optional API key, and initial instructions.
  • Flags that survive a resume. Model, effort, context, and permission mode are stored per session and rebuilt after --resume, which the CLI drops on its own.
  • Parent/child trees. Spawn a child with a typed edge — blocking (the parent shows blocked until it finishes) or tangential (spun off with context).
  • Scrollback snapshot. A resumed session repaints its prior conversation instantly instead of showing an empty terminal.

Communication & automation

Sessions coordinate through a message bus

Every app-spawned session gets a filesystem outbox and a one-time preamble teaching it to write there. The app drains each outbox and routes messages up to the parent or down to a named child, injecting them as fresh turns using only the session's native tools.

  • State-aware delivery. A message lands only when the target is idle or waiting, never mid-work, and is buffered until then.
  • Trust gate and global pause. No link routes messages until you trust it, and one switch freezes all routing without losing anything.
  • Message log. A header badge opens a record of every routed hop — from, to, text, and status — so autonomous coordination stays auditable.
  • Manual send / broadcast. Push a prompt into one managed session or many at once without switching to each terminal.

Categories & artifacts

Keep client, business, and personal work apart

Sessions live in hard-separated categories, each with its own color, optional emoji, and rail label. Client work never bleeds into personal, and each collection reads at a glance. An artifact drawer renders what a session produced without leaving the app.

  • Per-category notifications. Any class — needs-permission, question, done — can be loud for clients and quiet for personal.
  • Artifact preview. Images, SVG, audio, syntax-highlighted code, Markdown, and RTF render in a drawer over the terminal, each with its own error boundary.
  • Session-scoped detection. The drawer shows only what this session produced, staying accurate even in a shared project directory.
  • Reveal in Finder. The artifact list is sortable and timestamped, with per-item Open and Reveal in Finder.

How it works

Three steps to a managed fleet.

1

Install and open

Download the macOS build and launch it alongside your existing Claude Code setup. No daemon runs, and nothing is installed inside your sessions.

2

Adopt and launch

Sessions you already started in any terminal appear automatically. Start new managed sessions from the composer, sorted into categories.

3

Watch and triage

The beacon bar and overview grid show what needs you. Jump to any waiting session in a click, and the state you'd forget is held across restarts.

Honest status

A solo project in active beta.

This is an independent tool built by one person. It works and it's in daily use, but it leans on parts of Claude Code that aren't a public API. Read the details before you rely on it.

  • Version v0.20.0  A solo project in active beta.
  • Platform macOS on Apple Silicon only. No Intel or other-OS build.
  • Requires The Claude Code CLI already installed, plus a Claude subscription and/or an Anthropic API key.
  • Coupling It integrates with the Claude Code transcript format, session registry, hook payloads, and terminal rendering, none of which are a public API. Breakage after an upstream Claude Code release is expected, with no support SLA.
  • Affiliation Not an official Anthropic product. Independent, and not affiliated with or endorsed by Anthropic.
